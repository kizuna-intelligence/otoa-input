# 解説文書の用語規律 — 分かりやすい日本語用語で概念を説明する

## 適用場面

解説書・概要説明・入門資料・論文まとめ・レビュー解説・基礎知識資料など、読者に概念を理解させることが目的の文書全般。新規執筆・加筆・推敲のいずれにも適用する。

## 原則

1. 略語・英語専門用語(例: KD, OPD, RLVR, MDP, exposure bias)は、**その用語・その対象そのものを直接説明する文脈でのみ**使ってよい。例: 「OPD (On-Policy Distillation) とは何か」を定義する節、原論文の固有名・手法名・数式記号・API 名への言及。
2. **概要説明・概念説明の本文では略語・英語専門用語を使わない。**
3. 代わりに、文書の冒頭(または当該概念が最初に登場する節の頭)に**用語リスト**を置く:
   - 各専門用語に**分かりやすい日本語の用語**を割り当てる。定訳があれば定訳を使う(knowledge distillation → 知識蒸留)。定訳がなければ意味の核が伝わる日本語用語を**新しく作り**、原語・略語を括弧で併記する(例: on-policy distillation → 自己生成文の上での蒸留(OPD))。
   - 以後の概念説明は、この日本語用語だけで書く。
4. **用語は文書間・文献間で揃える。** 同じプロジェクトの複数の解説で、同じ概念には同じ日本語用語を使う。プロジェクトに用語表(glossary)ファイルを 1 つ作って再利用し、新しい用語を割り当てたら追記する。

## 理由(この規律が守られるべき根拠)

概要説明の目的は概念の獲得であり、未定義の略語は読者に暗記と文脈復元の負荷をかけ、理解をそこで止める。逆に、対象を直接説明する場面では原語そのものが説明対象なので使用が正当になる。また、文献間で訳語が揺れると同じ概念が別物に見え、複数論文の比較・接続という解説の価値そのものが壊れる。対応する日本語がない用語が多いのは事実だが、それは「作らない理由」ではなく「作って揃える理由」である。

## 手順

1. 書き始める前に、文書に登場する専門用語・略語を列挙する。
2. プロジェクトの用語表ファイルがあれば読み、既存の割り当てを再利用する。なければ `glossary.md` を作る。
3. 未割り当ての用語に日本語用語を与える。意味の核を表す短い名詞句にする(音写カタカナの羅列で済ませない)。
4. 文書冒頭に用語リスト(日本語用語 / 原語・略語 / 一行定義)を置き、本文は日本語用語で書く。
5. 対象の直接説明(原論文の紹介、数式、コード)では原語を使ってよいが、初出時に用語リストとの対応を示す。

## 検証

- 概要・概念説明の段落に、用語リストで定義していない略語・英語専門用語が残っていないか読み直す。
- 本文の用語が用語リストおよびプロジェクト用語表と一致しているか確認する。
- 新しく作った日本語用語を用語表ファイルに追記したか確認する。
