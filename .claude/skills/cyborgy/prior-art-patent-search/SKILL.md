# 先行特許調査

先行技術調査の判断と進行をAgent側で行う。検索は `patent-search` APIを基本とし、必要に応じてJ-PlatPat、Google Patents、Espacenet、Patentscope、USPTO、arXiv等を補完利用する。旧 `patent-research` APIや固定LLM調査jobを前提にしない。

## 入力と成果物

入力として発明説明、クレーム案、基準日、対象国、既知文献を確認する。基準日が不明でも調査は開始できるが、公開日の適格性判断は「要確認」とする。

途中経過と最終レポートに次を残す。

- 構成要素表
- 日本語・英語の検索語彙表
- 実行した検索式、対象source、ヒット件数、調整履歴
- 使用したFI・Fターム・IPC・CPCと選定理由
- 候補文献一覧とトリアージ理由
- 全文確認した文献の個票
- 要素対応表、新規性・進歩性評価、脅威ランク
- 調査範囲、失敗した検索、留保事項

## 1. 発明を検索可能な要素へ分解する

発明を3〜6個程度の独立した構成要素へ分解する。各要素を specific（具体構成）、functional（作用・機能）、generic（上位概念）の3階層で言い換える。発明の核が要素の組合せにある場合は組合せを明示する。

さらに発明全体について、製品・技術分野を示すdomain語と、弁別的機能を示すtech語を分ける。低レイヤーの実装語だけに寄せず、上位カテゴリ、機能語、特許特有の「手段」「部」等も含める。

## 2. 日本語から英語へ検索語を展開する

各階層で日本語の表記揺れ、同義語、上位語、略語、機能表現を作り、それぞれを英訳する。英語だけを独立に増やして日本語との対応を失わない。

単語検索に加え、domain語×tech語の複合検索式を機械的に作る。同じ概念の言い換えはOR、異なる必須要素はANDで組み合わせる。0件または過大件数になった式は分割・上位化・具体化し、変更履歴を残す。

## 3. 検索を段階的に実行する

最初に `patent-search` APIで `source=jp` を使い、日本語検索を行う。必要に応じて `us`、`foreign`、`all` を使う。1回の取得件数はAPI上限内に抑え、語彙や分類を変えて反復する。APIが使えない場合はJ-PlatPat等を直接調べる。

検索順序は次を基本とする。

1. 単一要素で母集団を把握する
2. 核となる要素のAND検索で絞る
3. domain×techの複合検索で共起文献を探す
4. 近接文献のFI・Fターム・IPC・CPCを逆引きして分類検索する
5. 最重要文献の引用・被引用を双方向に追う
6. 類似文献の主要出願人について関連出願を展開する
7. 非特許文献が脅威になり得る場合はarXiv等を補完する

外部検索と本文取得は相手サービスへ負荷をかけないよう逐次または低並列で行う。同じ失敗を無制限に再試行しない。ネットワーク・読取エラーは最大3回を目安に再試行し、失敗を記録して他のsourceへ切り替える。

## 3.1 全文・請求項の入手経路

要約や書誌だけでは判断できない。**請求項の原文を読むまで結論を出さない。**入手は次の経路を順に試す。

**Google Patents は使えないことがある。**環境によっては HTTP 503 で遮断され、実ブラウザ経由でも同じ結果になる。数回試して駄目なら見切りをつけ、下記へ移る。Espacenet も応答しない環境がある。

| 対象 | 経路 | 備考 |
|---|---|---|
| 米国（登録・公開） | `https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/<番号>` | 登録は7-8桁、公開は11桁（US2025/0191571 → `20250191571`）。認証不要。**画像PDFなのでテキスト抽出は不可** |
| 日本 | J-PlatPat をブラウザ操作 | 簡易検索に文献番号を入れて検索。結果の公開番号や登録番号をクリックすると別タブで文献表示が開く。「請求の範囲」「詳細な説明」は折りたたまれているので「開く」を押してから本文を取る |
| 欧州 | EPO publication server | `https://data.epo.org/publication-server/rest/v1.0/publication-dates/<YYYYMMDD>/patents/<番号>NWB1/document.html` で本文HTMLが直接取れる。公開日と種別コードが要る |
| 国際 | WIPO Patentscope | `https://patentscope.wipo.int/search/en/detail.jsf?docId=WO<番号>` 。Full Text タブから請求の範囲と明細書が取れる。PDF直接取得は captcha で塞がれることがある |

**画像PDFの読み方。**USPTO の公報PDFはテキスト層を持たない。OCR を用意できない場合は、**請求項のページを画像として描画して直接読む**のが速い。`pdftoppm -r 150 -png -gray -f <開始> -l <終了>` で十分に読める。請求項は末尾にあるので、総ページ数から逆算して最後の2ページを描画する。図面が出たら文章のページまで前へ戻る。

**表紙による仕分け。**件数が多いときは、まず全件の1ページ目（名称・要約・代表図）だけを描画して仕分ける。2件を横に並べた画像にすると読解の回数が半分になる。ここで分野違いを落としてから、残ったものの請求項を読む。

**ファミリーを使う。**欧州や国際の請求項が取れないときは、同一ファミリーの米国登録特許を探して代替する。ただし**各国で請求項は異なる**ので、代替したことをレポートに明記する。逆に、同一開示で複数世代ある米国継続出願は、**親の独立請求項が最も広い**ことがある。世代をまたいで確認する。

**請求の範囲は全独立項を読む。**請求項1だけでは足りない。装置・方法・プログラム・媒体で範囲が異なることがあり、従属項に核心が置かれていることもある。従属記載は日本語では末尾に、英語では冒頭に現れるので、抽出を自動化する場合はその違いに注意する。

**登録の有無を必ず確認する。**公開公報の請求項は権利範囲ではない。侵害の検討では、登録公報（B）の請求項と、審査で限定されたかどうかを見る。J-PlatPat の検索結果一覧に登録番号とステータス（「特許 有効」「年金の支払い」等）が出る。

## 4. 候補をトリアージする

タイトル、要約、出願人、分類だけで最終判断せず、全文確認の優先順位を付ける。

- A: 複数の構成要素または中核構成を開示し、新規性・進歩性を強く脅かす
- B: 1要素に強く対応する、同一分野・近い課題・共通作用を持つ
- C: 用語一致だけで中核構成との対応が薄い

A、Bを優先して請求項と明細書本文を読む。候補を捨てる場合も理由を残す。検索順をそのまま関連度順とみなさない。

## 5. 全文を要素単位で比較する

各文献について書誌、公開日、優先日、出願人、ファミリー、要約、独立請求項、関連する実施形態を確認する。本発明と引用文献の一致点・相違点を構成要素ごとに記録する。

名称、図示、記述粒度だけの違いを技術的相違と誤認しない。相違点を次に分類する。

- technical_effect: 引用文献にない具体構成と作用効果
- design_choice: 数値・配置の最適化、均等物置換、単なる組織化
- terminology: 呼称・表記だけの違い
- domain: 適用分野だけの違い
- none: 実質的差分なし

## 6. 新規性・進歩性を評価する

新規性は、単一文献が発明の全必須要素を明示または実質的に開示するかで判断する。

進歩性は、主引用発明との差分を副引用・周知技術で埋める動機付けがあるかを、技術分野、課題、作用・機能、引用文献中の示唆から評価する。設計事項、単なる寄せ集め、汎用AI・コンピュータ手段の通常適用は否定方向の材料とする。予測困難な効果、阻害要因、新しい機能的相互作用は肯定方向の材料とする。

相違がdesign_choice、terminology、domain、noneだけなら、実質的差分が弱いことを明記する。発明説明を言い換えただけの文を相違点として扱わない。

全構成要素について新規性または進歩性を否定する十分な証拠が揃った場合は、追加検索を打ち切ってよい。ただし、どの文献がどの要素を覆うかと終了理由を記録する。検索前の一般論だけで全調査を省略しない。

## 7. 脅威ランクとレポート

文献ごとに次のランクを付け、根拠を示す。

- 最高: 単一文献で新規性を害する可能性が高い
- 高: 主引用として進歩性を強く圧迫する
- 中: 組合せ引用または限定追加で回避可能
- 低: 背景技術としての関連に留まる

レポートは結論を先にし、次の順でまとめる。

1. 結論と脅威上位文献
2. 発明の要素分解
3. 検索方法、語彙、検索式、件数、分類
4. 文献個票
5. 要素別比較表
6. 脅威ランキング
7. クレームで残る差分と追加調査事項
8. 留保事項

## 留保

- 見つからなかったことは不存在の証明ではない。
- 未公開出願は原理的に発見できない。
- 公開日・優先日・先行技術適格性を必ず確認する。
- 新規性・進歩性や引用可能性の最終的な法的判断は弁理士へ確認する。
